# Use cases

These are planned behaviors; **UC-01 (login + workspace picker), the first UC-02 slice (telegram/pasted connections, encrypted secrets, manual destinations), UC-03 (workspace contacts, handles, neutral mention tokens, mention previews), the first UC-04 slice (immutable revisions, destination selection, per-destination previews), the first UC-05 slice (publish now: idempotent submissions, telegram text delivery, ADR-015 states), the first UC-06 slice (read-only publication history: filtered/paginated list + fail-closed detail), the first UC-07 slice (durable retry jobs/leases/worker, bounded backoff, owner retry/reconcile, UNKNOWN reconciliation) the first UC-08 slice (separate remote edit/delete actions on confirmed deliveries via a Telegram remote actor; original delivery preserved), the first UC-09 slice (restore an earlier revision as a new immutable revision + optimistic version-conflict guard; never last-write-wins) the first UC-10 slice (one-time schedules: explicit timezone + DST resolution, frozen revision/payload hash, at-most-one publication per schedule within the +15 min cutoff) the first UC-11 slice (duplicate a post into a new independent draft in the same workspace; approval/schedules/outcomes not copied) and the first UC-12 slice (in-app notification events: durable, deduplicated, redacted, workspace-scoped, shown on the dashboard) and the second UC-12 slice (webhook channels: SSRF-guarded URLs per arc42 §8, sealed HMAC signing secrets, signed deduplicated outbox delivery with bounded backoff and a 3-attempt budget via Flyway V12 `notification_channel`/`notification_delivery`) and the third UC-12 slice (SMTP channels via Flyway V13 on the same outbox: shared SSRF host rules + canonical port/TLS mapping, hand-rolled SMTP client with RFC 5321 semantics, sealed SMTP password with its own AAD purpose) and the first UC-13 slice (private media library + per-revision attachments with mandatory alt text; authenticated-only download, no public hosting, publish of media-attached revisions blocked fail-closed for platforms without upload support) and the second UC-13 slice (telegram direct upload of the private bytes via `sendPhoto`/`sendMediaGroup`, V11 per-delivery media snapshot, media-aware payload hash, alt-text transmission limitation shown) and the third UC-13 slice (outgoing image-metadata stripping into a fixed-at-upload derivative — only stripped bytes are ever uploaded, private originals keep their metadata) and the fourth UC-13 slice (short-lived revocable import grants via Flyway V15 `media_import_grant`: HMAC-signed expiring permit-all URLs with `no-store` serving the stripped derivative, revoked on confirmed import, per-grant fetch limit, `supportsMediaImport` flag) and the fourth UC-12 slice (connection/bridge-failure events via Flyway V14 `connection_id` on `notification_event`: redacted CONNECTION_FAILED/CONNECTION_RECOVERED events emitted only on connection health-state transitions with episode-sequenced keys, enqueued to the same webhook/SMTP outbox, dashboard-linked to the accounts page; and the fifth UC-12 slice (rate-limited shared-outage summaries: redacted `PROVIDER_OUTAGE` events keyed `outage:<platform>:<UTC-hour>`, at most one per platform per hour per workspace, emitted on UNKNOWN-stuck deliveries); and the final UC-12 polish (test notification names the workspace and exact recipient)) are implemented as of 2026-11-16, and the first UC-14 slice (ADR-010 experimental gate: opt-in flag off by default, WhatsApp Business permanently excluded, `whatsapp-status`/`signal` unavailable without a passed feasibility probe, permanent “experimental / unofficial” label on the accounts page; no schema change) is implemented 2026-11-17, and the second UC-14 slice (destination-kind gate: only the verified kind per experimental target — `status` for whatsapp-status, `message` for signal — with Signal story blocked and never substituted by a chat message; no schema change) is implemented 2026-11-17, and the third UC-14 slice (config-bound, startup-validated feasibility records via `app.experimental.feasibility` plus a wired-bridge-adapter check — a target needs flag + record + adapter before it can be available; no schema change) is implemented 2026-11-17** — see their review logs. All tenant operations require an explicit workspace, including jobs and callbacks. One owner login can manage every v1 workspace. [Plan.md](../../Plan.md) defines delivery phases; [ADR-015](../adr/ADR-015-publication-lifecycle-and-recovery.md) owns delivery states. All 16 use cases were cross-checked against the ADRs on 2026-11-13; each document records the outcome in its review log.
